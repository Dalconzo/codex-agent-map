# Codex Mission Control Wrapper: Project Spec

## Goal

Build a local wrapper and visual dashboard for running multiple Codex sessions across Git worktrees.

The system should show, in near real time:

- Which Codex agents are running
- Which Git worktree each agent is using
- Current branch, dirty file count, and recent file activity
- Agent task/status from heartbeat files
- Repo/worktree tree with agent location badges
- Clickable/hoverable nodes showing details
- Continuously refreshing local UI in a command-prompt-inspired style

The first prototype should not modify Codex internals. It should wrap Codex processes and collect status externally.

Why Wrapper First
Do not fork Codex for v0.
The wrapper gives 80% of the value without owning Codex internals:
Process alive/dead state
Worktree path
Branch
Dirty files
Recently modified files
User-provided task description
Heartbeat timestamps
Optional logs
Codex has documented areas around CLI/app/worktrees and automation, but for this prototype the safer path is external observation and wrapper orchestration rather than depending on unstable internals. OpenAI’s Codex docs list CLI, App worktrees, local environments, app server, SDK, and automation surfaces, which makes external integration the right initial direction.
User Workflow
Example usage:
cmc run \
  --agent codex-auth-1 \
  --repo ~/projects/my-app \
  --worktree ~/projects/my-app-auth \
  --task "Refactor auth/session boundary"
Then open:
cmc dashboard
or:
python backend/server.py
Dashboard appears at:
http://localhost:8765
Wrapper Requirements
Command
Implement a CLI command:
cmc run --agent <agent_id> --repo <repo_path> --worktree <worktree_path> --task "<description>" -- <codex args...>
Example:
cmc run \
  --agent codex-1 \
  --repo ~/repo \
  --worktree ~/repo-auth \
  --task "Fix auth tests" \
  -- codex
The wrapper should:
Validate repo path exists
Validate worktree path exists
Start Codex inside the worktree
Record child process PID
Write heartbeat JSON every 1 second
Continue until Codex exits
Mark final status as exited, failed, or killed
Heartbeat Schema
Each agent writes:
{
  "agent_id": "codex-1",
  "pid": 18422,
  "repo_path": "/Users/david/projects/my-app",
  "worktree_path": "/Users/david/projects/my-app-auth",
  "branch": "feature/auth-refactor",
  "cwd": "/Users/david/projects/my-app-auth",
  "task": "Refactor auth/session boundary",
  "status": "active",
  "last_seen": "2026-04-23T22:41:12Z",
  "uptime_seconds": 318,
  "dirty_file_count": 4,
  "dirty_files": [
    "src/auth/session.py",
    "tests/test_auth.py"
  ],
  "recent_files": [
    {
      "path": "src/auth/session.py",
      "modified_at": "2026-04-23T22:40:55Z"
    }
  ],
  "last_event": "process alive"
}
Allowed statuses:
starting
active
idle
exited
failed
stale
unknown
Heartbeat files should live at:
~/.codex-mission-control/heartbeats/<agent_id>.json
Git Scanner Requirements
Create git_scan.py.
Functions:
get_branch(path: str) -> str
get_dirty_files(path: str) -> list[str]
get_worktrees(repo_path: str) -> list[WorktreeInfo]
get_recent_files(path: str, since_seconds: int = 300) -> list[RecentFile]
get_repo_tree(path: str, max_depth: int = 4) -> RepoTreeNode
Use subprocess first:
git -C <path> branch --show-current
git -C <path> status --porcelain
git -C <repo> worktree list --porcelain
Avoid scanning ignored folders:
.git/
node_modules/
.venv/
venv/
dist/
build/
target/
__pycache__/
.cache/
.next/

Agent Location Heuristic
For v0, locate an agent using:
Priority order:
current_file from heartbeat if present
Most recently modified dirty file
Current working directory
Worktree root
Attach agent badge to that node.
Stale Detection
If heartbeat age:
< 5 sec: active
5–30 sec: delayed
> 30 sec: stale
process dead: exited/failed
Backend should compute this, not frontend.

Important Design Rule
Keep the wrapper, backend state model, and frontend rendering separate.
Bad:
UI directly shells out to git and reads heartbeat files
Good:
wrapper writes heartbeat
backend builds normalized state
frontend renders normalized state
This makes the project much easier for coding agents to build and debug.

My estimate:

- **Turn 1:** coding agent builds wrapper + heartbeat + simple backend.
- **Turn 2:** agent builds React dashboard with live updates.
- **Turn 3:** fix integration bugs, real Codex launch path, styling.
- **Turn 4:** polish graph layout, details panel, stale detection, packaging.

So: **2 turns for ugly-but-working**, **3–4 turns for a prototype you’d actually use**.
